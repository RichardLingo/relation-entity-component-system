概要与目标

本 RECS 子项目旨在提供一个小型、可嵌入的 relation-entity-component-system 核心库，满足科研与仿真场景中对高效实体管理、关系构造与向量化运算的需求。目标是在保持轻量的同时，提供清晰的 API、良好的文档与若干示例以便用户快速上手。

范围与受众

- 范围：核心内存存储与基本操作（实体添加、属性管理、关系表、矩阵到关系的转换、示例脚本）。不包含渲染、网络同步或复杂 RECS 框架（system/dispatcher 的调度逻辑）。
- 受众：研究人员、仿真开发者、小型游戏/模型原型开发者。

关键用例

1. 初始化实体池并批量添加实体用于仿真实验数据的存储。
2. 将邻接或权重矩阵转换为边表并基于关系进行查询与过滤。
3. 动态添加实体属性并进行向量化计算（例如批量更新速度/位置）。
4. 在不改变外部 uid 的情况下移动或压缩内部存储。

功能性需求

- FR1: 支持创建具有自定义属性（dtype）的实体池，并能以 O(1) 批量添加实体。
- FR2: 支持添加/删除/启用/禁用实体；提供 boolean 活跃掩码与活跃索引查询接口。
- FR3: 提供 Relation 类用于高效边表存储，支持按 src/dst 查询。
- FR4: 提供从稠密矩阵转换为 Relation 的工具（阈值过滤、属性 dtype 继承）。
- FR5: 在扩容时正确初始化新分配的区域（数值类型为 0，非数值为 None）。

非功能性需求

- NFR1: 内存使用尽量紧凑，避免多余的 Python 对象；优先使用 numpy ndarray。
- NFR2: 批量操作（添加/查询）应尽量向量化以获得较好性能。
- NFR3: 向后兼容旧 ECSEngine API（暴露 d 字典等），不破坏现有用户代码。
- NFR4: 文档齐全（用户手册、开发者指南、示例）以减少上手成本。

成功指标

- 文档覆盖率：基本文档与示例完整（DEVELOPER_GUIDE.md, USER_MANUAL.md, demos）。
- 性能：对 1e6 规模的简单批量添加场景，内存与时间开销在可接受范围（需基准测试）。
- 兼容性：对现有依赖 ECSEngine 的 demo 能无改动或仅需小适配运行。

路线图与里程碑

- 0.1: 提供当前实现与基础文档（已包含在本仓库）。
- 0.2: 添加单元测试与 CI 配置；提供基准测试脚本。
- 0.3: 提供序列化接口（save/load）与多池关系管理工具。

风险与假设

- 假设用户在现代 Python 3.8+ 环境下工作，并安装了 NumPy。
- 风险：对于极端规模（亿级实体）的使用，当前内存模型可能不足以高效管理，需要分块或外部存储支持。
- 风险：直接使用 object dtype 属性会显著降低性能，并带来内存碎片与 GC 开销。
